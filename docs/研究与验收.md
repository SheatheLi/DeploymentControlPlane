# Full-stack｜持久部署控制面与崩溃窗口恢复｜技术增强研究与验收

## 核心认知与真实问题

Worker 拉起业务进程后在状态晋级前崩溃，外部服务可能已运行但持久控制面并不知道；若只检查 PID 会有重用和错误接管风险。

**本阶段判断：** 这是有实际工作指向的研究切片，而不是已证明行业领先的旗舰成果。验证充分性要以专业生态的真实对象、成熟强基线和个人技术接管为准。

## 实际技术栈（运行平台／框架／基础设施）

FastAPI/Pydantic、SQLite WAL、HTTP/JSON、本地 Python 子进程、浏览器 HTML、Python subprocess；Java/Spring Boot、PostgreSQL、容器/集群编排尚未实现。

## 专业机制与来源（不是技术栈的同义词）

租约 fencing token、generation CAS、幂等请求、由子进程自注册的启动账本、不可猜测的健康身份 nonce、重启后恢复接管与陈旧实例隔离。

**参考来源或技术体系：** Kubernetes controller reconciliation/finalizer 模式与常见持久工作流；这里实现的是单机简化版，不是 Kubernetes operator。

研究方法中的已知算法不声明原创；移植和组合也只有在真实负载胜过成熟替代方案时才能被称为独立优势。

## 已实现结果及边界

通过实际 HTTP Worker 和磁盘 SQLite 执行 5 次控制器重启后的合法启动接管（5/5），以及 5 次新的 desired generation 覆盖旧工作时的陈旧实例拒绝（5/5）；所有实例均用版本加 nonce 校验，不直接用未确认的 PID 执行 kill。

运行命令与逐项数据见 `evidence/增强对照.json`。代码中包含新增专项测试。原有基准是历史证据，不得混用不同源码版本。

## 强对照与失败结构

子进程注册前的崩溃窗口仍无法恢复；无租约心跳和跨机器实例；旧进程被隔离但尚未自动回收；数据库为 SQLite；缺容器和 Spring/Postgres 真正端到端。

当前专业领域问题仍然未被完整攻克；如果迁移到真实系统后新方法不胜强基线，优先否决候选机制，不通过更多技术名词修饰。

## 下一步应攻克的高压课题（未实现，禁止作为当前简历事实）

增加进程启动前的持久意图和子进程重注册/过期回收，Docker 容器标签/身份、Postgres 事务与真实反向代理、Spring/React 多租户权限及随机崩溃测试。

## 工程化验收规则

- 真实对象：必须有可独立复现的上游机制问题、第三方真实数据或真实服务负载。
- 算法价值：比较成熟且相关的专业方法，而不是只比较自制弱方案。
- 量化：必须带分母、负载、环境、反例、消融、P95/P99 或效用与成本。
- 发布：可安装/构建、运行入口、干净环境测试，单项目根目录，不使用轮次编号组织。
- 求职：Target 与 Current 分开；未被本人追踪、修改、调试与答辩的技术不作为已掌握声明。

# 研究与验收｜Deployment Control Plane

## 问题重构
真实发布在重复请求、worker 租约过期、并发新旧发布与外部执行副作用之间发生状态分叉或旧版本覆盖新版本。 与其说“需要增加技术栈”，不如说需要进入真实运行时/模型/决策对象，比较成熟可行机制以及适用边界。

## 可核查原始动机
历史曾出现 npm ci 失败、缺真正执行/健康切换/回滚；项目不能只制作一套 API/Outbox Mock。

## 参考成熟设计与外部问题
- K8s deployment stuck: https://github.com/kubernetes/kubernetes/issues/135483
- Argo Rollouts semantics: https://github.com/argoproj/argo-rollouts/blob/master/docs/FAQ.md
- Kubernetes deployment docs: https://kubernetes.io/docs/concepts/workloads/controllers/deployment/

这些资料证明对应技术问题或技术方法存在；**本项目没有声称已复现上述所有 Issue，也不默认已有方案不足。**

## 技术竞争结构

- 强基线：选择本领域不用新机制的可用方法，在同一输入/任务下测量。
- 核心候选：持久 desired/active 状态机、idempotency key、事务性 job 队列、带单调 lease token 的 CAS fencing、真实本地 HTTP 子进程部署、健康门控后发布 active 版本、历史审计和浏览器管理界面。
- Oracle：独立正确性/模拟真值/精确检索/事务日志（随领域而异）；严禁将辅助 Oracle 泄露给真实预测决策。
- 否决规则：若候选输给同预算成熟方案、缺少真实价值、不能解释失败，必须 Pivot 或 Kill，不能只调简历文案。

## 已完成的实验与指标
真实本地 HTTP 子进程 5 次顺序发布：5/5 成功健康门控后升级 active，启动到健康的五次样本最大耗时 697.0ms（仅 5 次，非生产 P95）。

## 不等价的声明
本机测试进程不是 Docker/Kubernetes 部署；没有真实外部流量切换/多节点 leader election；健康检查以本地固定接口验证为主。
